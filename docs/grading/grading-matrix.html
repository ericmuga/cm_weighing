How a carcass is graded

Every BG1021 carcass runs through the same five-step scorecard, worked from the reference grading sheet. Weight only enters the picture at step four — and only when it's actually needed.

  1. 01 QA scores six visual attributes — Dentition, Fat Cover, Bruising/Blemishes, Fat Colour, Meat Colour, Muscle Conformation — and the points sum to Verdict 1.
  2. 02 Verdict 1 is checked against every grade's scoring band. The bands overlap by design — FAQ and Standard, for instance, share the same floor of 10 — so one score can land inside more than one grade at once.
  3. 03 If only one grade's band fits, that's the classification. Settlement weight isn't consulted at all.
  4. 04 If more than one grade fits — a tie — carcass weight breaks it. Weight is banded into five tiers and can only ever pull the grade down, never up: Verdict 2 = Verdict 1 + weight tier, used purely to rank the tied candidates.
  5. 05 The system records its own suggestion alongside whatever QA finally saves — it never overwrites their call. That's shadow mode, below.

Shadow mode

The scorecard computes verdict1 / verdict2 / auto_classification for every carcass and stores it alongside whatever grade QA actually saves — it suggests, never decides. Each saved row is tagged auto or manual depending on whether QA's own choice matched the suggestion, and a tied flag marks the rare case where weight couldn't clearly settle a tie between grades.

That agreement trail is what tells us when it's safe to let the system decide on its own — it isn't there yet.

Fixed this session

Four issues surfaced while tracing why the "Downgraded?" flag on graded carcasses wasn't resolving the way QA expected. All four are live now.

AreaWhat was wrongWhat changedStatus
Weigh-in visibility QA had no way to see the grade a carcass was assessed at when it was weighed in — only the grade assigned after QA's own review. The grading table now shows the weigh-in code alongside the QA classification, side by side. Resolved
Downgrade flag, structural "Downgraded?" was comparing QA's grade against a code re-generated from that same grade — a comparison that could almost never disagree, so genuine downgrades read as "No". It now compares QA's final grade against the independent code captured at weigh-in, before QA ever saw the carcass. Resolved
FAQ & Standard rules The downgrade check had no rule at all for the FAQ or Standard grades — carcasses graded either way sat permanently unresolved. Both grades added. Since weigh-in never assigns an FAQ or Standard code of its own, either verdict now correctly flags as a downgrade. Resolved
Weight required too early Auto-grading refused to suggest any grade without a settlement weight — even when the visual score alone was already unambiguous. Weight is now asked for only when Verdict 1 genuinely ties between two or more grades. Resolved

Verified against the reference sheet's worked examples — 9 automated tests, 41 assertions, passing.
